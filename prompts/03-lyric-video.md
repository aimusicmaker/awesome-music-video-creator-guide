# 03 · Lyric window

[All recipes](README.md) · [Home](../README.md) · [Editing help](../docs/editing.md)

**Level:** Easy · **Editing target:** 16 seconds · **Status:** original brief, not render-tested.

## Bring these inputs

A short lyric excerpt you own and its corresponding audio. The included practice beat is instrumental; use title cues with it, not fake lyrics.

**Starting route:** [Short Music Video Generator](https://musicmaker.im/free-short-music-video-generator/). Use only input modes and durations currently offered by the tool. Longer plans require separate clips and editing.

## Image direction

Use this to create or choose a reference image. For text-to-video, the motion prompt can be used without an image when the tool permits it.

```text
A rain-streaked window at dusk with soft distant lights, dark low-detail center area for text, no readable signs, no people.
```

## Copy the motion prompt

```text
Rain beads move slowly down the window. Distant amber bokeh remains soft. Fixed camera, dark uncluttered central area, stable exposure. No letters, symbols, faces, or sharp moving objects.
```

## Music direction

For an original song or instrumental; skip this if you already have audio.

```text
Intimate ballad: gentle piano, sparse brushed percussion, soft bass, an original vocal melody with space between phrases. Use only lyrics you may reuse.
```

## Assemble the edit

For a 16-second practice edit, generate four short background takes with the same motion prompt and trim each to four seconds. With a vocal track, adjust the cuts to the actual phrase lengths. Add one or two lyric lines per phrase in the editor; set each cue by listening. Keep the same background through a complete phrase before cutting.

## If it fails

If words are hard to read, darken a text panel instead of regenerating the background. If the lyric arrives early, adjust its cue on the waveform.

**Before you export:** Every word matches the song; lines remain readable on a phone and do not collide with interface overlays.

Change one variable per retry and keep your best take. Use the [brief template](../starter-kit/brief-template.md) to record the actual inputs, output settings, and changes.
